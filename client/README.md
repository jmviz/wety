# wety-client

The frontend for [`wety.org`](https://www.wety.org/).

It's a [Vite](https://vite.dev/) app using [SolidJS](https://www.solidjs.com/) and [TanStack Router](https://tanstack.com/router); there is no UI library. Everything is set in [Brill](https://brill.com/page/resources_fontsdownloads) (free for non-commercial use), served from `public/fonts`.

## Search

There is one input (`src/search/SearchBox.tsx`), which reads like a dictionary citation: a small-caps language chip and a word. Typing offers words in the chip's language, with matching languages in a second group; typing an exact language name followed by a space swaps the chip, and Backspace on an empty word (or clicking the chip) edits it. `/` focuses it from anywhere. The chip, the reader's languages and the current view are remembered in `localStorage` (`src/prefs.ts`).

On a word's page the search sits beside the wordmark on one line, with a link to the about page (`src/About.tsx`, `/about`) at its end; the dotted frame is the home page's, whose foot links to the about page and to GitHub. Below it, the word's title line (`src/search/WordTitle.tsx`) gives the term, a switch between its etymologies when it has several, its first sense and the tree's size. Then one row of controls (`src/search/ViewBar.tsx`): the four views of the word (etymology, descendants, cognates, constellation) on the left; on the right, the languages a tree is drawn in, the connections it follows (`src/settings/ConnectionsPanel.tsx`) and how rows are shown (`src/settings/DisplayPanel.tsx`), each opening a panel. Trees are drawn in the reader's languages (remembered, and always including the word's own), with "show all" (`all=1` in the URL) beside the count; naming languages in the panel puts them in the URL (`lang=`). Words formed from a word of the same language (limelight under lime) are left out unless the panel asks for them (`within=1`). Cognates add the word's trail below the row (`src/ety/Trail.tsx`): the word back to its oldest form that is the same word, then that form's sources, then "ultimately from" the forms at the ends of its etymology (roots, with affixes and the rest one click away). The tree is the descendants of the bold one: by default the oldest word on the trail along its head line (each step's sole source, else its head, else its one root), so tabula's tree starts at PIE *steh₂-, and a compound with neither stops it (astronomy's starts at ἀστρονομία); any other step or source starts it there instead (`root=` in the URL). Starting as far back as the ancestry goes is deliberate: a word's relatives are the whole family of its oldest known ancestor, not only those of its oldest same-word form (tabula's would otherwise stop at Proto-Italic *taðlā). The walk never crosses a possible or doubtful link (wolf would otherwise reach *stel-), but it does follow a disputed reading that has no preferred alternative.

## Trees

The outline and the chart are plain HTML; there is no SVG or layout library. The constellation places its own boxes and draws its lines in one SVG.

- **Descendants / cognates** (`src/ety/OutlineTree.tsx`) are an indented outline: nested `<ul>`/`<li>`, a `<details>` on every node that has children (leaves are plain rows), and connectors drawn with CSS borders. Subtrees use `content-visibility: auto` with a size hint from the number of visible rows, so very large trees stay cheap to scroll. A branch's children are built the first time it is opened.
- **Etymology** (`src/ety/ChartTree.tsx`) is a chart read like the outline, oldest at the top and the word at the bottom, laid out entirely with flexbox and border pseudo-elements; the derivation mode sits on the connector. A word's alternative etymologies ("from A or B") are branches of their own, each with its mode and "or": all are drawn when none is preferred, otherwise the preferred one with an "or N more" control. A possible or doubtful link is dashed and its word marked "?"; a mode a wety rule inferred (a form-of sense, a root category) is underlined; "origin unknown" stands where the source says so, and a dashed box with the language's name and "exact source uncertain" where it names a language or family but no word ("From Welsh").
- **Constellation** (`src/constellation/`) is a map of the words of the searched word's language that share its root, on a dark canvas whatever the page's theme. Initial framing and camera moves use the browser’s visible viewport, including retained pinch zoom and its offset, so refresh frames the visible screen rather than the larger layout viewport. Initial framing keeps the root near centre, allowing up to a tenth of the screen’s width or height of movement to fit uneven branches at a larger scale; it shifts only where an edge needs more room. The root sits in the middle; round it is a blob for each branch of the language tree the words came down (Proto-Germanic, Proto-Italic), listing the branch's words in the reader's language, the searched word marked. A collapsed node previews its subcognate groups on separate lines in the same order as the expanded branches, keeping related words together within each line. Lone descendants share one section, sorted by corpus usage frequency, rather than taking one line each; larger subcognate groups stay separate. Both folded descendant clusters and actual historical root cards use a plain language label floating above them. Each language gets one heading above its highest visible node; it transfers to the next visible node as the reader pans, and stays attached to the node as both scroll off-screen. Labels and descendant boxes are never pinned to the viewport. Descendant clusters have no internal language heading. Each preview row highlights on hover or keyboard focus; clicking opens only that row's historical source and descendant paths. Untouched rows remain together in the original labelled box until its final row opens. A proto-language row can span several roots; later-language rows each retain their actual source, including separate rows where distinct sources lead to the same English spelling. Related subgroups inside one row keep their line breaks and open as one action. Sibling sources feeding the same language share a single descendant preview, with separate incoming connections; this combines the Latin previews below Proto-Italic *portā and *portus without combining the historical words. That preview uses the same row interaction, continuing outwards until the reader's language is reached. Each new click places its source cards immediately below the remaining descendant box, ahead of older branches; sources from one click stay together in their lane order. Newly revealed cards and cables receive a subtle accent for four seconds, replaced by the next click, without highlighting unchanged previews. On every expansion, the camera fits the newly revealed historical sources through their furthest exposed descendants, including automatic expansions and language headings. It uses normal reading scale when they fit and zooms out when necessary to keep both ends visible. The newly revealed branch owns the vertical centre. Remaining previews and older siblings can contribute horizontal context when they fit at the same scale, but never pull the new root and its descendants below the centre. Shared roots never pull in words from untouched rows: each breakout retains its own word scope. Opened historical sources sit in separate compact cards, centred on their own subtrees, with one floating heading per language in the visible window, shared with its descendant previews. The preserved preview box occupies its own lane beside those cards. A shared incoming stem connects sibling sources without crossing their cards; the first opened card's top-right corner folds the language group back into its preview. Language changes between adjacent child nodes leave room for the floating headings. Clicking a row whose historical lineage has no forks opens every recorded stage through to the reader’s language, even if its endpoint is a list of several modern words (Proto-Germanic → German → kindergarten, kinder, etc.). Distinct historical source words or multiple language lanes count as forks; the final modern-word list does not. A branching node initially opens one stage, unless every immediate child has exactly one final descendant. In that case, all of those child paths open through to the reader’s language together (Old French porter → Middle English disporten/reporten → English sport/report, plus English port). A single child with multiple descendants keeps the whole set folded at that stage. Opened siblings in the same language and root-family branch share their expansion depth: later clicks match the deepest opened sibling. Once one sibling reaches the reader's language, other clicked siblings follow all of their paths there even when they need more intermediate stages. Deepening a path also advances its already-open siblings; untouched siblings stay folded, and a corner click can still close one individually. Every opened node containing one named word uses one compact row, including intermediate stages such as Proto-West Germanic and Old English. Its language stands just above the entry, never inside the row; visible nodes in the same language share that label. English endpoints use the same treatment. One-word paths retain every recorded intermediate language stage: Ancient Greek → Latin → French → English is never drawn as an Ancient Greek → English jump. Families with four or more visible stages, or whose normal card widths exceed the available viewport width, size individual historical-word cards and one-word endpoints to their content and language label, with 24px connections between compact cards. This includes short side branches such as cynrēde; multiword modern lists and folded descendant previews keep their normal size. The decision uses normal widths rather than the already-compressed layout so resizing cannot oscillate between sizes. Long chains such as smile retain every historical stage without repeating full-width cards; folded previews keep their usual spacing. A one-to-one path uses compact lines for the word and meaning beneath their language labels, with the final word beside its source (Old Norse um → English ombudsman). A head whose next language step is the one final word has that word in a blob as wide as the rack and as tall as the head's row: it stands level with the row, named as the row is (the dot, the language, the word in italic), at the end of a short line, and such heads are kept together in the middle of the rack, with the other heads' blobs above and below them. A lane's blob opens the same way, further out, and its lane grows to take what comes off it, so nothing lands on its neighbours. Time runs outward within each root branch: language stages occupy approximate chronological columns, so Late Latin stands beyond Latin and before Old French even when both Latin stages come straight from the same root. The positions use the existing dating export (`data/products/dating/language_periods.json`), bundled as `virtual:layout-periods`: midpoints of complete periods, the reported central value of estimates, and interpolation between dated language stages where dates are incomplete. These are layout hints, not new dating claims; source dates remain unchanged, and graph edges plus minimum readable gaps take precedence over a strict time scale. Parallel language branches overlap horizontally with a small chronological stagger; only a direct parent-to-child link needs a full box of space. Connectors use horizontal and vertical runs joined by rounded curves, including routes around obstacles. They turn in the same short gutter beside the parent before running level, so long links do not cross their shorter siblings. Straight diagonal segments are never used. Lines from the central root route around other branches' reserved space, so a tall sibling cannot hide a line and appear to be its source. For an opened cluster, the incoming cable meets the shared stem outside the first or last card with a smooth curve; its own invisible layout column is not an obstacle that forces a hooked detour. Final words and lists in the reader's language align along the outer edge of their root branch, beyond the full width of every earlier-language box with a clear gap, so shorter paths end beside longer ones; a one-word list uses the same compact line as other single-word nodes. So an opened head is drawn once. Historical source rows use Brill's italic for the word and regular upright Brill for its meaning, both in the same soft gray. The central root disc retains its emphasized meaning. Connecting cables have no endpoint or junction dots. Every expanded node, including a compact one-row node, folds from its top-right corner (no visible icon). Clicking anywhere on the central root circle resets the constellation to its initial collapsed layout and zoom. Page load, refresh and reset compose the starting branches around the root, allowing a small shift from centre to fit asymmetric branches at a larger scale. Initial font and layout measurements can refine that fit until the first interaction; afterward, automatic initial fitting stops. A blob that grows finds a new seat round the others, which stay put, and one that shrinks keeps the room it had; the canvas is dragged or scrolled, and zoomed with the buttons or Ctrl/⌘ and the wheel. It draws the cognates tree (`/cognates/:id`) in the word's language alone, starting from the first of the word's ultimate ancestors rather than the cognates view's default, so hundred starts at PIE *deḱ- and not at Proto-Germanic *hundaradą; "start from" offers the others (`root=` in the URL). A reversible display experiment currently hides Undefined Root entries and their entire descendant paths, in both previews and expanded nodes. The graph and placeholder construction are retained; set `HIDE_UNDEFINED_ROOTS` in `branches.ts` to false to restore them.

Constellation routes temporarily hide the surrounding Wety masthead, search, word title and view/settings navigation and use the full viewport. The canvas controls remain available. Set `CONSTELLATION_ONLY` in `src/App.tsx` to false to restore the normal page shell; other routes keep it throughout.

`branches.ts` does the grouping: words of the hub's own language are passed through, a head is the first word of another language, and heads are grouped by their exact language. A node's heading names every word in its rows: Latin, Late Latin and Medieval Latin each have their own node, never an Old Latin heading with later-language rows. A hub at the top of its family (a reconstructed word of a language with no ancestor, such as Proto-Indo-European) instead has the family's fixed branches, the languages that come straight from its own, so words with no recorded form in that branch share one “Undefined Root” row there. Opening Proto-Hellenic therefore gives its recorded Proto-Hellenic forms plus one “Undefined Root” row, whose Ancient Greek words stand together in a single Ancient Greek blob; and a word of the reader's language recorded as coming straight from such a hub (tagged with the root, its descent not given) is left out, since none does. A word of any other later language that is only tagged with the root (Old French intellectuel under *leǵ-) belongs to its family's branch but did not come straight from it (no Old French word comes straight from Proto-Italic): it stands there under an “Undefined Root” head, in the first language on the way down that is not a stage of a proto-language or family (Latin), for the word it came through, which is not recorded. A tagged word of that language itself (Latin legenda) is a head as any other. The API sends no family for a language, so the language tree comes from the Wiktionary export the graph was built from, as the module `virtual:lang-tree` that `vite.config.ts` builds (the build needs `data/registry/inputs.json` and the export it names). `layout.ts` gives each root branch its own fixed direction and cable departure point. A branch needing more room moves farther out along that direction, never into a sibling's direction; the first view fits the resulting arrangement to the window; a rack is seated as one thing, its lanes included, and its lanes' blobs are placed from it outwards. Blobs list the selected representatives: single words only, leaving out phrases and proper nouns (the searched word excepted). For English they omit paths that jump directly from Latin, Ancient Greek, a proto-language, or a language placed at or before 200 CE to modern English, including English derivatives on those paths. A recorded later intermediary (Late Latin, French, Old English, Middle English) keeps its path visible; the searched word itself is always kept. This applies to collapsed lists and opened nodes, including with rare words shown. For English, SCOWL supplies the vocabulary filter: tier 50 normally and tier 35 on paths through Latin and its stages, including later intermediaries such as French. Latin-origin affixes must qualify without their boundary hyphens. The searched word is always kept. Corpus usage from wordfreq supplies finer ordering within those tiers. A conservative representative pass leaves out a word only when the graph records extra prefix/suffix formation from a shared historical source, a shorter base is present, and that base is at least 0.8 Zipf points more frequent. A common proto ancestor or spelling resemblance alone is insufficient. Each subcognate group has a soft budget that grows with its size; especially frequent words, unknown-frequency words and the searched word can exceed it. The same selection governs collapsed previews and expanded nodes. Rare mode bypasses this selection. Words formed with an affix are left to the affix: where the graph has a word coming down through an affix or combining form (cosmology, theology and etymology through Ancient Greek -λογία and -λογος), the word is left out and the English affixes below the hub ("-logy", "-logue") are listed in its place, while a word formed from the root word itself (apology, trilogy) stays. This goes by the graph's own lines of descent, not by spelling, so a word in "-logy" that Wiktionary derives some other way (zoology, ontology) is still listed. The graph has no word frequencies. Vocabulary filtering uses the SCOWL word lists (the `wordlist-english` package, sizes 10 to 70, with 10–50 shown by default, or 10–35 for Latin-origin English words), which `vite.config.ts` builds into the module `virtual:common-words`, loaded with the constellation alongside a wordfreq score subset (together about 600 kB gzipped); "rare and derived words" in the display panel, off at first, lists them all again. Other languages have no such list: every word is listed, likeliest-known first by what the graph has (single lower-case words, several entries or parts of speech, nearness). Collapsed previews use the expanded branch order recursively, so each subgroup's words stay together; repeated spellings appear once and the existing word filters still apply. A word's details open on hover, and on a click only where the word is not inside something that is itself clicked (a branch or head that cannot be opened).
- `src/ety/model.ts` turns the API's JSON into the display model: stable keys, subtree counts and language summaries, display order (the searched item's ancestry first, then closest languages, then largest subtrees), the default collapse policy (path to the searched item plus a visible-row budget, spent on branches that pass the same word on before new formations), and the client-side filters (connection types, hidden languages) from the panels. Filters never re-fetch.
- Word details open in a popover (`src/ety/NodePopover.tsx`) on hover or click; on touch devices it is a bottom sheet. It uses the Popover API and CSS anchor positioning, with JS placement as a fallback. Its Origin list gives each of the word's etymologies with who asserts it (Wiktionary's editors, on which page and section, or the wety rule that inferred it) and the works it follows (footnotes, References), from `/origin/:id`.

## Links and API

URLs name a word, not a position in the server's data: `/<view>/<language code>/<term>`, plus `?ety=N` when Wiktionary numbers the word's etymologies and `lang=<code>` for each descendant language (spaces in terms are written as underscores, as on Wiktionary). `src/search/types.ts` builds and parses them; `src/state.ts` loads one by asking the server's `/resolve` for the word and its homographs, then fetching the tree by the word's numeric ID. Numeric IDs only mean something within one graph build, so the client sends the build's version (`graph=`) along with them; if the server answers 409, it has been redeployed and the page reloads, which resolves the URL afresh. When a word has several etymologies, a line under the view bar switches between them (`src/search/Homographs.tsx`); a link that names several without a number shows a chooser.

The client fetches an item lazily (`/item/:id`) when its glosses are absent, a word's origin (`/origin/:id`) when its details open, and a language (`/lang/:code`) when a link names one that doesn't occur in the tree.

## Local development

You'll need the `wety` API server running first — see the root README for that.

```bash
npm install
npm run dev
```

The dev server starts at `http://127.0.0.1:8000`. Changes are hot-reloaded.

Frequency scores are a static English usage snapshot through about 2021 from [wordfreq 3.1.1](https://github.com/rspeer/wordfreq), by Robyn Speer. The adapted subset in `data/english-frequencies.json` is under [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/); see the [upstream attribution notice](https://github.com/rspeer/wordfreq/blob/master/NOTICE.md), including Google Books Ngrams, the Leeds Internet Corpus, Wikipedia, ParaCrawl, OpenSubtitles 2018, and freely available SUBTLEX data by Marc Brysbaert and collaborators. Regenerate it from the repository root with `uv run --isolated --no-project --with wordfreq==3.1.1 python client/scripts/build-word-frequencies.py`. Normal client builds read the checked-in subset and need no Python or live frequency service.

Run the constellation grouping checks with `node --test tests/*.test.mjs`.
