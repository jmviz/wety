# wety-client

The frontend for [`wety.org`](https://www.wety.org/).

It's a [Vite](https://vite.dev/) app using [SolidJS](https://www.solidjs.com/) and [TanStack Router](https://tanstack.com/router); there is no UI library. Everything is set in [Brill](https://brill.com/page/resources_fontsdownloads) (free for non-commercial use), served from `public/fonts`.

## Search

There is one input (`src/search/SearchBox.tsx`), which reads like a dictionary citation: a small-caps language chip and a word. Typing offers words in the chip's language, with matching languages in a second group; typing an exact language name followed by a space swaps the chip, and Backspace on an empty word (or clicking the chip) edits it. `/` focuses it from anywhere. The chip, the reader's languages and the current view are remembered in `localStorage` (`src/prefs.ts`).

On a word's page the search sits beside the wordmark on one line, with a link to the about page (`src/About.tsx`, `/about`) at its end; the dotted frame is the home page's, whose foot links to the about page and to GitHub. Below it, the word's title line (`src/search/WordTitle.tsx`) gives the term, a switch between its etymologies when it has several, its first sense and the tree's size. Then one row of controls (`src/search/ViewBar.tsx`): the four views of the word (etymology, descendants, cognates, constellation) on the left; on the right, the languages a tree is drawn in, the connections it follows (`src/settings/ConnectionsPanel.tsx`) and how rows are shown (`src/settings/DisplayPanel.tsx`), each opening a panel. Trees are drawn in the reader's languages (remembered, and always including the word's own), with "show all" (`all=1` in the URL) beside the count; naming languages in the panel puts them in the URL (`lang=`). Words formed from a word of the same language (limelight under lime) are left out unless the panel asks for them (`within=1`). Cognates add the word's trail below the row (`src/ety/Trail.tsx`): the word back to its oldest form that is the same word, then that form's sources, then "ultimately from" the forms at the ends of its etymology (roots, with affixes and the rest one click away). The tree is the descendants of the bold one: by default the oldest word on the trail along its head line (each step's sole source, else its head, else its one root), so tabula's tree starts at PIE *steh₂-, and a compound with neither stops it (astronomy's starts at ἀστρονομία); any other step or source starts it there instead (`root=` in the URL). Starting as far back as the ancestry goes is deliberate: a word's relatives are the whole family of its oldest known ancestor, not only those of its oldest same-word form (tabula's would otherwise stop at Proto-Italic *taðlā). The walk never crosses a possible or doubtful link (wolf would otherwise reach *stel-), but it does follow a disputed reading that has no preferred alternative.

## Trees

The outline and the chart are plain HTML; there is no SVG or layout library. The constellation places its own boxes and draws its lines in one SVG.

- **Descendants / cognates** (`src/ety/OutlineTree.tsx`) are an indented outline: nested `<ul>`/`<li>`, a `<details>` on every node that has children (leaves are plain rows), and connectors drawn with CSS borders. Subtrees use `content-visibility: auto` with a size hint from the number of visible rows, so very large trees stay cheap to scroll. A branch's children are built the first time it is opened.
- **Etymology** (`src/ety/ChartTree.tsx`) is a chart read like the outline, oldest at the top and the word at the bottom, laid out entirely with flexbox and border pseudo-elements; the derivation mode sits on the connector. A word's alternative etymologies ("from A or B") are branches of their own, each with its mode and "or": all are drawn when none is preferred, otherwise the preferred one with an "or N more" control. A possible or doubtful link is dashed and its word marked "?"; a mode a wety rule inferred (a form-of sense, a root category) is underlined; "origin unknown" stands where the source says so, and a dashed box with the language's name and "exact source uncertain" where it names a language or family but no word ("From Welsh").
- **Constellation** (`src/constellation/`) is a map of the words of the searched word's language that share its root, on a dark canvas whatever the page's theme. The root sits in the middle; round it is a blob for each branch of the language tree the words came down (Proto-Germanic, Proto-Italic), listing the branch's words in the reader's language, the searched word marked. A collapsed node previews its subcognate groups on separate lines in the same order as the expanded branches, keeping related words together within each line. The whole blob is one thing to click. Its words come from one word of the branch or from several (its heads), and the click opens them all at once: the blob becomes a rack, each head a row in it, named with its meaning, and each head's own branches' blobs stand in a lane beside the blob, the lanes one under another in the rows' order and centred on the blob, which keeps its own size, so the lines from heads to blobs fan out side by side without crossing (on the side away from the root; the name row or top-right corner folds it back into one list). A blob with one head is a rack of one row, and only the root is a disc, which names no language. Every newly revealed child node is checked on its own: if it contains one named source word and one final word, it opens automatically and shows both. This also applies when several such child nodes come from a larger rack (Middle English stride, unclose, quiver and brim); a child node with multiple source words or destinations stays folded. Every opened node containing one named word uses one compact row, including intermediate stages such as Proto-West Germanic and Old English. One-word paths retain every recorded intermediate language stage: Ancient Greek → Latin → French → English is never drawn as an Ancient Greek → English jump. A one-to-one path uses compact lines for the language, word and meaning, with the final word beside its source (Old Norse um → English ombudsman). A head whose next language step is the one final word has that word in a blob as wide as the rack and as tall as the head's row: it stands level with the row, named as the row is (the dot, the language, the word in italic), at the end of a short line, and such heads are kept together in the middle of the rack, with the other heads' blobs above and below them. A lane's blob opens the same way, further out, and its lane grows to take what comes off it, so nothing lands on its neighbours. Time runs outward within each root branch: language stages occupy approximate chronological columns, so Late Latin stands beyond Latin and before Old French even when both Latin stages come straight from the same root. The positions use the existing dating export (`data/products/dating/language_periods.json`), bundled as `virtual:layout-periods`: midpoints of complete periods, the reported central value of estimates, and interpolation between dated language stages where dates are incomplete. These are layout hints, not new dating claims; source dates remain unchanged, and graph edges plus minimum readable gaps take precedence over a strict time scale. Parallel language branches overlap horizontally with a small chronological stagger; only a direct parent-to-child link needs a full box of space. Connectors turn in the same short gutter beside the parent before running level, so long links do not cross their shorter siblings. Lines from the central root route around other branches' reserved space, so a tall sibling cannot hide a line and appear to be its source. Final words and lists in the reader's language align along the outer edge of their root branch, beyond the full width of every earlier-language box with a clear gap, so shorter paths end beside longer ones; a one-word list uses the same compact line as other single-word nodes. So an opened head is drawn once. The root's disc and a rack's row name the word in Brill's italic, quietly, and beside it at the same size its first meaning, upright and in Brill's bold: the meaning is the one that carries. Every expanded node, including a compact one-row node, folds from its top-right corner (no visible icon). Clicking anywhere on the central root circle resets the constellation to its initial collapsed layout and zoom. A blob that grows finds a new seat round the others, which stay put, and one that shrinks keeps the room it had; the canvas is dragged or scrolled, and zoomed with the buttons or Ctrl/⌘ and the wheel. It draws the cognates tree (`/cognates/:id`) in the word's language alone, starting from the first of the word's ultimate ancestors rather than the cognates view's default, so hundred starts at PIE *deḱ- and not at Proto-Germanic *hundaradą; "start from" offers the others (`root=` in the URL). `branches.ts` does the grouping: words of the hub's own language are passed through, a head is the first word of another language, and heads are grouped by their exact language. A node's heading names every word in its rows: Latin, Late Latin and Medieval Latin each have their own node, never an Old Latin heading with later-language rows. A hub at the top of its family (a reconstructed word of a language with no ancestor, such as Proto-Indo-European) instead has the family's fixed branches, the languages that come straight from its own, so words with no recorded form in that branch share one “Undefined Root” row there. Opening Proto-Hellenic therefore gives its recorded Proto-Hellenic forms plus one “Undefined Root” row, whose Ancient Greek words stand together in a single Ancient Greek blob; and a word of the reader's language recorded as coming straight from such a hub (tagged with the root, its descent not given) is left out, since none does. A word of any other later language that is only tagged with the root (Old French intellectuel under *leǵ-) belongs to its family's branch but did not come straight from it (no Old French word comes straight from Proto-Italic): it stands there under an “Undefined Root” head, in the first language on the way down that is not a stage of a proto-language or family (Latin), for the word it came through, which is not recorded. A tagged word of that language itself (Latin legenda) is a head as any other. The API sends no family for a language, so the language tree comes from the Wiktionary export the graph was built from, as the module `virtual:lang-tree` that `vite.config.ts` builds (the build needs `data/registry/inputs.json` and the export it names). `layout.ts` gives each root branch its own fixed direction and cable departure point. A branch needing more room moves farther out along that direction, never into a sibling's direction; the first view fits the resulting arrangement to the window; a rack is seated as one thing, its lanes included, and its lanes' blobs are placed from it outwards. Blobs list every word that passes, with no cut-off: single words only, leaving out phrases and proper nouns (the searched word excepted). For English they omit paths that jump directly from Latin, Ancient Greek, a proto-language, or a language placed at or before 200 CE to modern English, including English derivatives on those paths. A recorded later intermediary (Late Latin, French, Old English, Middle English) keeps its path visible; the searched word itself is always kept. This applies to collapsed lists and opened nodes, including with rare words shown. For an English word they also leave out obscure words beyond SCOWL tier 60, tightened to tier 35 on recorded paths through Latin (including its named stages and later intermediaries such as French); Latin-origin affixes must also qualify, checked without their boundary hyphens and the plain derivatives of a word already listed (forgiveness, forgiving and unforgiven beside forgive, lexicologist beside lexicology), and list the commonest first. Words formed with an affix are left to the affix: where the graph has a word coming down through an affix or combining form (cosmology, theology and etymology through Ancient Greek -λογία and -λογος), the word is left out and the English affixes below the hub ("-logy", "-logue") are listed in its place, while a word formed from the root word itself (apology, trilogy) stays. This goes by the graph's own lines of descent, not by spelling, so a word in "-logy" that Wiktionary derives some other way (zoology, ontology) is still listed. The graph has no word frequencies, so this goes by the SCOWL word lists (the `wordlist-english` package, sizes 10 to 70, with 10–60 shown by default, or 10–35 for Latin-origin English words), which `vite.config.ts` builds into the module `virtual:common-words`, loaded with the constellation (about 360 kB gzipped); "rare and derived words" in the display panel, off at first, lists them all again. Other languages have no such list: every word is listed, likeliest-known first by what the graph has (single lower-case words, several entries or parts of speech, nearness). Collapsed previews use the expanded branch order recursively, so each subgroup's words stay together; repeated spellings appear once and the existing word filters still apply. A word's details open on hover, and on a click only where the word is not inside something that is itself clicked (a branch or head that cannot be opened).
- `src/ety/model.ts` turns the API's JSON into the display model: stable keys, subtree counts and language summaries, display order (the searched item's ancestry first, then closest languages, then largest subtrees), the default collapse policy (path to the searched item plus a visible-row budget, spent on branches that pass the same word on before new formations), and the client-side filters (connection types, hidden languages) from the panels. Filters never re-fetch.
- Word details open in a popover (`src/ety/NodePopover.tsx`) on hover or click; on touch devices it is a bottom sheet. It uses the Popover API and CSS anchor positioning, with JS placement as a fallback. Its Origin list gives each of the word's etymologies with who asserts it (Wiktionary's editors, on which page and section, or the wety rule that inferred it) and the works it follows (footnotes, References), from `/origin/:id`.

## Links and API

URLs name a word, not a position in the server's data: `/<view>/<language code>/<term>`, plus `?ety=N` when Wiktionary numbers the word's etymologies and `lang=<code>` for each descendant language (spaces in terms are written as underscores, as on Wiktionary). `src/search/types.ts` builds and parses them; `src/state.ts` loads one by asking the server's `/resolve` for the word and its homographs, then fetching the tree by the word's numeric ID. Numeric IDs only mean something within one graph build, so the client sends the build's version (`graph=`) along with them; if the server answers 409, it has been redeployed and the page reloads, which resolves the URL afresh. When a word has several etymologies, a line under the view bar switches between them (`src/search/Homographs.tsx`); a link that names several without a number shows a chooser.

The client fetches an item lazily (`/item/:id`) when its glosses are absent, a word's origin (`/origin/:id`) when its details open, and a language (`/lang/:code`) when a link names one that doesn't occur in the tree.

## Local development

You'll need the `wety` API server running first — see the root README for that.

```bash
npm install
npm run dev
```

The dev server starts at `http://127.0.0.1:8000`. Changes are hot-reloaded.

Run the constellation grouping checks with `node --test tests/*.test.mjs`.
