# Review without an available human specialist

The project can proceed with model reviewers. A human review is optional additional evidence, not a prerequisite for source recovery, annotation, scenario comparison, software changes, a further pilot, or a documented editorial decision. The user has no capacity to supply a reviewer. Do not send that dependency back to them.

Use a fresh session for a second source-based assessment where practical. A different model family can add methodological diversity, but is not mandatory and does not establish statistical independence. A second session of the same model is useful process separation; another pass in the current conversation is useful self-audit. Label them accordingly. None of these is an additional historical source or a vote for the true date.

## Obstacles and practical responses

| Difficulty | Work the agent can do | Residual limit and disposition |
|---|---|---|
| Anchoring on earlier annotations | Give a fresh session complete primary files and neutral questions. Freeze its first annotations before it reads existing claims, summaries, code expectations or reviews. | Instructions in a shared repository are procedural separation, not access control. Record any exposure; an exposed review remains useful but is not blind. |
| Shared model errors and memorized literature | Seek falsifying passages, reconstruct arguments from sources, use another model family when available, and check numerical claims with separately written calculations. | Model diversity does not prove independent errors; pretraining exposure is unknown. Report model-reference agreement, not expert-validated historical accuracy. |
| Limited family-specific expertise | Work through the actual correspondence sets, donor adaptations, competing reconstructions, cited examples and counterexamples. Read methodological objections and replies. Require evidence for each inference. | Unfamiliar or underdetermined judgments remain explicitly unresolved. This limits that assertion, not all research in the family. |
| Phonetic symbols and defective PDF extraction | Inspect rendered pages, compare multiple extractors and font mappings, retain image locators, and separate visual transcription from original parsed text. | If a symbol remains ambiguous, preserve alternatives and withhold only inferences that depend on its exact identity. Do not silently normalize it. |
| Missing full text or supplements | Try publisher, author, repository, archived deposits and cited derivative data; log acquisitions, failures and document identity. | A catalog page is not full text. Missing material cannot be invented; quarantine affected conclusions while progressing on accessible sources. No need to wait for a human to fix access. |
| Unavailable old software or runtime | Inspect code and inputs, reproduce narrow quantities in the root environment, and compare algorithmic conventions and numerical tolerances. Install/run the original environment only when useful and feasible. | A reimplementation is not an original-environment reproduction. Missing traces cannot establish convergence; retain author-reported diagnostics as such. |
| Study and result dependence | Trace dataset, cognate, calibration, prior and repository reuse. Compare actual analysis identities and sample sets. | Unknown dependence remains unknown. Two papers, files or reviewers never automatically increase historical confidence. |
| Ambiguous stage/clade/catalog identity | Compare literal labels, sampled taxa, historical definitions and documentary samples; record exact/subset/overlap/unresolved relationships for the particular use. | Catalog correspondence does not authorize date transfer. An unresolved mapping need not prevent source-specific claims. |
| Disagreement between reviews | Compare source locations and intermediate reasoning; reproduce computations, search counterexamples, and resolve demonstrable mistakes. Freeze a separate reconciliation record. | Do not majority-vote or force agreement. A sound argument can resolve a disagreement; genuine historical alternatives remain separate. |
| No expert reference labels | Create transparent model-authored reference annotations, independently annotated before comparison where possible. Use mechanical checks and deliberately constructed negative controls. | Measure agreement with this reference and disclose annotation uncertainty; do not call it human gold or historical truth. Useful extraction evaluation remains possible. |
| No genuinely held-out material yet | Reserve new project-unexposed passages and dependency clusters before prompts or labels are tuned on them; record selection, context and exposure. | Existing pilot material supports development diagnostics and fresh-session blind review, but cannot become held out from the project retroactively. Unknown pretraining exposure remains disclosed. |
| Long context and finite resources | Split by complete study/scenario, keep source locators and a coverage ledger, and reconcile across packets. Prioritize claims consequential for downstream use. | Uninspected sections stay uninspected. Targeted review need not be described as exhaustive, and an unfinished section does not block unrelated work. |
| Historical non-identifiability | Distinguish dates of evidence, model events and named stages; test alternative assumptions and derive only consequences that follow under each. | No reviewer can extract a unique language birth or borrowing date from evidence that does not identify it. Preserve the conditional result or unknown rather than waiting for someone to supply certainty. |

## Operational decision

Continue the IE and Sino-Tibetan packets now. Review can run alongside that work or follow it. Use the prepared [fresh-session handoff](model-review-prompt.md) for the Uralic audit when convenient. The task must produce its own annotations before seeing ours, then a source-based reconciliation, rather than merely reviewing this agent's conclusions.

If a fresh session is unavailable, do a structured adversarial self-audit: rederive the material from the original source, test a competing account, check numerical and semantic invariants, and record what changed. This is the default fallback, not a request for user intervention. It is sufficient to continue bounded research. Do not mark a second or independent review as completed.

The gate is the adequacy of evidence for the particular action. A source-specific assertion can be supported by a named model reviewer with exact evidence and the normal semantic/mapping checks. An explicit editorial decision can likewise be model-authored if its scenario and eligibility checks pass. Model proposals must still pass the ordinary import/decision workflow; agreement between sessions never imports or selects a date automatically. Historical defaults, code-specific export and broad ingestion require their substantive checks, not a human signature.

Record reviewer kind, model/version if exposed (otherwise unknown), session identifier, prior-context exposure, source/code/prompt hashes, review scope, tool limitations, and whether the first assessment was frozen before comparison. Preserve original annotations and reconciliations separately. Existing packet `independent_review: false` values describe past work and stay unchanged. A future review must disclose process separation and model dependence explicitly rather than treating a lone Boolean as sufficient provenance.

This replaces the earlier implication that independent human expertise or a separate held-out set must arrive before the next source packet can proceed. Review availability does not block the agenda; evidential limitations constrain only the claims or actions they actually affect.
