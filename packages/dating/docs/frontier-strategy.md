# Decision: try one Astra researcher before more harness tuning

Assessment: 20 September 2026. Prefer one tool-enabled Astra task for the next
bounded family dossier, using existing acquisition/provenance and deterministic
checks. Defer further multi-backend matrices, automatic model-review chains and
schema-development loops until this simpler baseline has been measured. This is
an operational recommendation, not a claim of measured quality superiority or a
change to publication eligibility.

The missing baseline is a **single responsible researcher**, not merely a stronger
model in every existing role. The retained Codex worker runs already requested
`gpt-6-astra` at medium effort. Those workers had research tools disabled and were
asked for constrained outputs over selected packets. An ordinary Astra task can
read methods, inspect figures, retrieve a missing source, reconcile an ambiguity
and write/check individual records within one continuing context. It need not
generate the entire family registry in one huge JSON response.

## What one family might cost

Official Astra Standard API rates are $10/M input, $1/M cached input and $50/M
output; separate cache writes are $12.50/M. Requests above 272K input tokens have
higher rates. These are API rates, not a conversion to a Pro weekly allowance.
[Astra pricing](https://developers.openai.com/api/docs/models/gpt-6-astra).

For short-context requests, the illustrative text estimate is
`10 × uncached_input_M + 1 × cached_input_M + 50 × total_output_M`.
Output includes non-visible generation; do not count the reasoning subset again.
[Token accounting](https://developers.openai.com/api/docs/guides/reasoning).

| Planning scenario, not a measured run | Cumulative uncached / cached input | Total output including reasoning | Text cost with assumed cache | Same traffic without cache |
| --- | --- | ---: | ---: | ---: |
| Prepared source packet | 80K / 0 | 15K | $1.55 | $1.55 |
| Bounded family session, roughly 3–6 substantive sources | 200K / 600K | 50K | $5.10 | $10.50 |
| Larger dossier | 600K / 3M | 100K | $14.00 | $41.00 |

All rows assume each individual request stays at or below 272K input; cumulative
session traffic is not context-window size. Separate cache writes could add $0.20,
$0.50 or $1.50 respectively if all new input is written to cache. Tool/image costs,
larger-than-assumed reasoning, retries and long-context/Fast pricing can increase
the total substantially. API web search is $0.01/call plus search-content tokens;
other retrieval products have their own costs. [API pricing](https://developers.openai.com/api/docs/pricing).

**A $5–15 planning allowance for a bounded dossier is reasonable to test, not a
quote or hard cap.** A broad, contested family's literature can exceed $50 or need
multiple explicitly scoped dossiers. A single one-million-token prompt is not the
economical default. Under an included Codex allowance there need not be an extra
cash payment, but usage still consumes that allowance. Official guidance says
model, context, reasoning, tools, retrieval and caching affect consumption; we lack
a defensible percentage-per-family forecast. [Codex usage guidance](https://learn.chatgpt.com/docs/pricing).

## Feasibility and expected quality

One session with tools is feasible for a bounded source-rich dossier. One request
without tools is unsuitable for open-ended literature research, access recovery or
checking an artifact. No session can manufacture missing historical evidence or
resolve every issue in Indo-European, Austronesian or another large family.

| Issue | Expected effect of one capable researcher | Remaining limit |
| --- | --- | --- |
| Lost context and repeated handoffs | Likely improves: the same agent owns sampling, methods and interpretation. | Large contexts can still obscure details; retain short source notes and exact evidence. |
| Schema/provider/envelope failures | Likely reduces: write and validate records incrementally using tools. | Mechanical validity is not entailment; an unsupported shape remains a gap. |
| Discovery/access | Can pursue actual gaps and use appropriate indexes rather than a fixed biomedical queue. | Paywalls, omitted figures and incomplete searches remain. |
| Event/role/epoch fidelity | Better contextual reasoning is plausible. | Astra itself made mistakes in existing runs; no measured superiority claim is available. |
| Self-review | One deliberate source-based pass avoids repeated full-family calls. | Correlated blind spots remain; do not label self-check independent review. |
| Throughput/cost | May sharply reduce coordinator intervention and development overhead. | A deep single session can cost more than successful cheap workers. Measure delivered utility, not call count alone. |

The earlier failed review envelopes do not mean every assertion was wrong, and
fewer validation failures in the new mode will not prove scientific improvement.
Apply the same source-fidelity standard and count unsupported event/role/date
substitutions, missing central evidence and residual unknowns. Do not compare a
polished narrative with the harness's entire structured error inventory.

## Changed operating policy

Use [the ready-to-run brief](single-astra-prompt.md): one fresh Astra task, no
subagents or other model calls, standard speed, bounded search/source/time limits,
incremental proposals, one self-check and one local correction pass. High effort
is a starting hypothesis; do not automatically use maximum effort. Finish with a
useful partial dossier when evidence or budget runs out. No code refactor is needed
to try this; retain scientific validators, provenance and publication separation.

Measure the **whole task**, including source reading and self-check, plus any later
coordinator effort. If precise task tokens are unavailable, report the measurement
gap; do not promise a hard token/cash cap from a prompt or an account-level meter.
Any follow-up should target named missing evidence, not restart the entire family.
Compare cost per source-supported useful assertion and central-source coverage,
with correlated self-audit limits disclosed. Consider cheaper specialist roles
again only after a repeatable single-agent baseline exists and a particular role
demonstrably reduces total cost without increasing serious errors.

The initial accounting assessment made **no additional model-worker calls** and changed no harness
runtime, model configuration, scientific inputs or published generations. It
replaces the next evaluation loop with a simpler research operating protocol.

The subsequent [executable single-frontier implementation and first live result](single-frontier.md)
now provide a Codex-subscription baseline, explicit Claude/OpenRouter profiles,
and measured worker usage. The earlier no-model-call statement applies to the
accounting assessment, not that later implementation/run.
