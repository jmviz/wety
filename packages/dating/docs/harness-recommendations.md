## Recommended workflow and instructions

1. **Plan the source inventory.** Identify family scope and source-specific entities, competing chronologies, major methodological critiques/replies and documentary/contact evidence. Search without requiring numerical dates. Treat missing abstracts, ambiguous screening and zero-claim central papers as follow-up work. Sample exclusions for recall; corrections and calibration discussions are eligible even without new ages. Discovery should produce a research question and completeness ledger, not a target number of dated languages.
2. **Acquire and classify documents.** Retain response bytes, hashes, identity/version, content type, access state and relationships. Distinguish article body, abstract, catalog entry, supplement, dataset, XML, trace, tree and correction. Record every known unacquired or unsupported file, including archive members excluded by type/size and incomplete APIs. Apply bounded retries and alternate legitimate primary routes; stop with a specific gap and affected assertions. A 403 is an access gap, not negative evidence.
3. **Prepare evidence by document and section.** Keep stable file/section/table/page identities and original text. Replace whole-paper concatenation with section-aware chunks and explicit coverage, carrying definitions, footnotes and table headings into local context. Retain overlap/deduplication provenance. Preserve every input sent to the model, not only a digest. Rendering/OCR should be triggered by suspicious text, not used to invent phonetics. A large context window does not demonstrate effective recall.
4. **Extract assertions before catalog mapping or synthesis.** Ask separately what was dated, the literal subject/sample, event, role, method, statistic/interval, native unit/epoch, scenario and dependencies. Return explicit unknowns and structured follow-up requests. Preserve contrary article/configuration statements without silently reconciling them. Link each assertion to its exact file and spans; do not quote the harness's inventory as source evidence. Compute conversions and routine statistics in code after semantic validation.
5. **Run deterministic and semantic checks separately.** Exact quotes/numbers are necessary provenance checks, not entailment. Check source identity, units, interval types, sample scope, priors versus results, conditional scenario membership, omitted negative evidence and dependency reuse. A source can be accurately quoted and historically unpersuasive. Add typed conflict objects rather than burying mismatches in summaries. Mechanical XML/log/tree checks should produce review evidence with declared scope; missing convergence diagnostics restrict posterior use, not all discussion of a paper.
6. **Review scenarios and map entities.** Use a capable reviewer on contested/complex arguments with original context. Keep source-first annotation separate from comparison against earlier labels. Route disagreement to explicit alternatives or a bounded adversarial self-audit; a human is optional. Mapping is a separate decision and never transfers dates through a catalog. Synthesis compares complete analyses and shows dependencies; no majority vote, newest-paper rule or endpoint stitching.
7. **Publish evidence with a run completion report.** Report discovered/accessed/parsed/supplied/reviewed sources separately, supported assertions by type, conditional model results, unresolved mappings, omitted subjects and gaps. Distinguish exhausted budgets from no evidence. Keep proposals and publication decisions separate. Every optional default must name its scenario and limitations; default selection is not required for a useful new-family run.

## Decisions after native-time repair

The [native-repair report](native-repair.md) tests the same fifteen retained targets
on each backend and keeps the failed review/circuit outcomes. It supports a narrow
engineering conclusion: models can restore native quantities, but a native-only
patch cannot repair a mistaken event label or contradictory qualification. Adding
more repair calls is not an adequate substitute for supplying the right evidence
and a faithful representation contract.

| Area | Current recommendation |
| --- | --- |
| Proposal representation | Use explicit prior family/location/SD/support, elapsed length and quantified relative offset types. They are implemented and offline-tested. Do not turn prior support into a posterior interval or project a relative offset into calendar years. Keep unsupported shapes explicit. |
| Source evidence | Preserve model text and actual source excerpts separately. Whitespace-only alignment now records exact source offsets and match method; it cannot change words or punctuation. Next bind table-header units/epoch definitions as explicit contextual evidence. A quote-only check currently misses BP supplied only by a table header. |
| Context selection | New sentence-sized epoch/prior/branch hints avoid oversized definition paragraphs. Selected/omitted spans remain visible. Context selection does not establish applicability to a secondary citation. |
| Repair strategy | Enable at most one native patch per selected original cell, followed by full-field source review within the same ledger. Default remains disabled unless the brief reserves calls. Do not request patches for every unknown: relative chronology without quantities should remain unknown. |
| Reviewer reliability | Source fidelity and historical certainty are different questions. Correctly retaining an uncertain hypothesis can be supported. Missing optional scenario labels alone should not cause uncertainty. Preserve valid judgments from failed batches, but withhold batch eligibility; partial recovery is not approval. |
| Models/effort | No universal strength increase is justified. Claude restored quantities but forced unsupported prior shapes and produced an inconsistent review. OpenRouter accepted the narrower schema, over-abstained on branch brackets and later truncated JSON. Codex produced two short incomplete outputs under this repair contract. Test the tightened contract on small identical targets before attributing these failures to model capability or changing defaults. |
| Provider/output budgets | The minimal OpenRouter profile is no longer purely a rejected API path: two repair batches completed. That is not full compact reliability. Retain actual finish/error metadata and distinguish truncation, schema validation and semantic errors. Adjust provider, model, effort or token limit only in a separately frozen comparison. |
| Failure accounting | The shared circuit correctly skipped later Codex repair/review cells. Do not route around it silently. A declared alternate reviewer can be part of a future brief; failed review coverage must remain visible. No human reviewer is required for a disclosed coordinator audit. |
| Discovery/throughput | The next substantive expansion should improve the existing queue's bibliography breadth and assertion-driven follow-ups, then run a new small cluster. The short schema checks should unblock that work, not initiate another prolonged source-tuning cycle. |
| Evaluation/publication | Nine calls yielded sixteen proposed patches, eleven mechanical passes, zero complete aligned review batches, and zero imports. Report those denominators separately. The new schema/recovery/alignment behavior is offline-validated; no post-run fix is retroactively a live-model success. |

The operating objective remains autonomous research with reviewable, source-specific
results. Unknowns, explicit shape gaps and partial coverage are usable outcomes;
they should guide bounded follow-up work rather than trigger fabricated dates or an
indefinite requirement to settle all pilot histories.
